# 译稿审校与润色

本文件是 `SKILL.md` 中「译稿审校与润色」的必读补充。

## 情况一：已有完整翻译过程

主 agent 与 subagent 分工：

1. 主 agent：将翻译偏好与目标整理为 `goal.md`；将 `translation.md` 复制为 `draft.md`。
2. 委派 subagent 执行审校并输出 `critique.md`。
3. 主 agent：读 `critique.md`，逐条回源原文核实；对成立项修订，保存 `revision.md`。
4. 主 agent：按「润色原则」通读 `revision.md` 进行最终润色，保存为 `translation.md`。

**委派 subagent 的 prompt 模板**：
```
你是译文审校者，请读取以下材料并输出 critique.md，严禁修改其他任何文件。

- 目标：{goal.md 路径}
- 原文：{原文路径}
- 待审译稿：{draft.md 路径}
- 术语表（如有）：{glossary.md 路径}
- 输出：{critique.md 路径}

要求：
1. 逐段对照原文与 draft.md。
2. 严格按「审校要点」检查，按「诊断报告格式」写入 critique.md。
2. 审校报告只记录可回源证伪的问题。禁止「我更喜欢另一种说法」等主观风格偏好。禁止为填满模板而编造问题。某类无问题可直接省略。

审校要点：{{...}}

诊断报告格式：{{...}}
```

## 情况二：直接提供原文与初稿

全部由主 agent 完成，但**仍须**走完 `goal.md` → `draft.md` → `critique.md` → `revision.md` → `translation.md` 全链。

1. 按前置准备中的要求确认翻译偏好与策略，落地为 `goal.md`。将用户提供的初稿保存为 `draft.md`。
2. 主 agent 同时作为审校者，严格对照原文和 `draft.md`，按“审校要点”生成 `critique.md`。
3. 主 agent 基于 `critique.md` 自身进行修订和润色，产出 `translation.md`。

## 审校要点

逐段对照原文与 `draft.md`，检查以下内容：

**准确性**：
- 核实事实、数字、观点、逻辑关系和论证结构
- 检查是否有意外添加、删除或改变的内容
- 原文结构性 Markdown（标题层级、链接、图片、代码块）是否保留；增强性格式（粗体、小标题）是否改善阅读而未破坏论证结构
- 检查术语一致性
- 术语首次出现时在译文后用括号标注英文原文；**仅首次**标注，后续不重复

**母语表达**：
- 标记读起来像「翻译」而非「写作」的句子——不自然语序、逐字硬译、生硬措辞
- 标记不适当地跟随原文句长的长句（CJK 目标语言应优先短句、并列结构）
- 对 CJK：检查多余连接词（因此/然而/此外）、被动语态滥用（被/由/受到）、名词堆叠、过度名词化
- 标记直译后在目标语言中不自然的隐喻
- 检查情感色彩与语域——口语化的原文是否被写成中性书面语，讽刺或幽默是否被抹平
- 说明可通过重组句子提升可读性的位置

**译者注**（若存在）：
- 译者注是否准确、简洁且确实有帮助
- 标记遗漏的理解难点，以及明显术语的过度注释（须与 `goal.md` 中的注释策略一致）

## 诊断报告格式（`critique.md`）

```markdown
## 准确性
- [问题]：[位置] — [描述]

## 母语表达
- [问题]：[示例] → [建议修改]

## 译者注
- [增/删/改]：[术语/段落] — [原因]

## 总结
[整体评估：X 处须修订，Y 处建议改进]
```

## 润色原则（`translation.md`）

在 `revision.md` 基础上做出版级质量的最终检查：

- 将整篇译文作为独立文章通读——是否像目标语言的母语内容一样流畅？
- 顺平仍然生硬的过渡表达
- 确保全文叙述声音和风格一致
- 最终术语一致性检查
- 核实格式是否正确保留

将终稿保存为 `translation.md`。
