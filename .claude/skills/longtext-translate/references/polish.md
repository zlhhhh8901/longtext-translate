# 译稿审校与润色

审校与润色是增强流程，用于降低误译风险，并使译文作为自然的目标语言文章成立。本流程非默认执行，仅当满足以下任一条件时触发：

- 用户明确要求精翻、审校、润色或发布级质量
- 译文预输出 token 数处于建议分片阈值，但因风险问题仍采取普通翻译模式
- 主 agent 在译后自检中发现系统性风险

执行总则：先诊断，后修订，再润色。具体流程覆盖两种情况：

1. **已有完整翻译过程**：译文由本技能前述流程逐步生成，上下文与中间文件完整。
2. **直接提供原文与初稿**：用户直接提交源材料与译文初稿，未经过翻译流程。

## 产物

审校与润色阶段会在输出目录中保留以下文件：

| 文件 | 作用 |
| --- | --- |
| `goal.md` | 翻译偏好与目标 |
| `draft.md` | 审校前译稿快照 |
| `critique.md` | 结构化、可证伪的独立审校报告 |
| `revision.md` | 基于审校意见修订后的译文 |
| `translation.md` | 最终译稿 |

## 情况一：已有完整翻译过程

主 agent 与 subagent 分工协作：

1. 将翻译偏好与目标整理为 `goal.md`，将当前 `translation.md` 复制为 `draft.md`。
2. 委派 subagent 读取 `goal.md`、`glossary.md`（如有）、原文和 `draft.md`，执行独立审校，严格按照“审校要点”和“诊断报告格式”生成 `critique.md`。
3. 主 agent 阅读 `critique.md`，逐条回溯原文确认问题是否成立，然后进行修订，产出 `revision.md`。
4. 主 agent 对 `revision.md` 进行最终润色，保存为 `translation.md`。

## 情况二：直接提供原文与初稿

所有操作由主 agent 完成，无需委派 subagent：

1. 按前置准备中的要求确认翻译偏好与策略，落地为 `goal.md`。将用户提供的初稿保存为 `draft.md`。
2. 主 agent 同时作为审校者，严格对照原文和 `draft.md`，按“审校要点”生成 `critique.md`。
3. 主 agent 基于 `critique.md` 自身进行修订和润色，产出 `translation.md`。

## 审校要点

逐段对照原文与译文，检查以下内容：

**准确性**：
- 核实事实、数字、观点、逻辑关系和论证结构
- 检查是否有意外添加、删除或改变的内容
- 原文 markdown 格式是否保留
- 检查术语一致性
- 术语首次出现时在译文后用括号标注英文原文。只允许首次标注，后续不重复

**母语表达**：
- 标记读起来像“翻译”而不是“写作”的句子——不自然的语序、逐字硬译、生硬措辞
- 对 CJK 目标语言：检查不必要的连接词（因此/然而/此外）、被动语态滥用（被/由/受到）、名词堆叠、过度名词化
- 标记直译后在目标语言中显得不自然的隐喻
- 检查情感色彩是否保留，而不是被抹平
- 说明哪些地方通过重组句子可以提升可读性

**译者注**（若存在则检查）：
- 译者注是否准确、简洁且确实有帮助？
- 标记遗漏的理解难点（需要注释）以及对显而易见术语的过度注释

## 诊断报告格式 (`critique.md`)

审校报告仅记录可回源证伪的问题，禁止填入主观风格偏好（如“我更喜欢另一种说法”）。无问题可省略。不要为填满模板而制造问题。

```
## 准确性
- [问题]：[位置] — [描述]

## 母语表达
- [问题]：[示例] → [建议修改]

## 译者注
- [增/删/改]：[术语/段落] — [原因]

## 总结
[整体评估：X 处严重问题，Y 处改进]
```

## 润色原则

完成修订后，由主 agent 对 `revision.md` 做出版级质量的最终检查：

- 将整篇译文作为独立文章通读——是否像目标语言的母语内容一样流畅？
- 顺平仍然生硬的过渡表达
- 确保全文叙述声音和风格一致
- 最终术语一致性检查
- 核实格式是否正确保留

将终稿保存为 `translation.md`。
