# 翻译工作流细节

此文件为每个工作流步骤提供详细指南。各模式共享这些步骤：

- **Quick**：仅翻译（不使用此文件中的步骤）
- **Normal**：第 1 步（分析）→ 翻译
- **Refined**：第 1 步（分析）→ 第 2 步（初稿）→ 第 3 步（审校）→ 第 4 步（修订）→ 第 5 步（润色）
- **Normal → 升级**：normal 模式完成后，用户可以继续执行第 3 步 → 第 4 步 → 第 5 步

所有中间结果都保存为输出目录中的文件。

## 第 1 步：内容分析

翻译前，分析源材料。将分析保存到输出目录中的 `01-analysis.md`。

### 1.1 内容摘要

- 这篇内容讲什么？核心论点是什么？
- 作者背景、立场和写作语境
- 原文的目的和预期受众

### 1.2 术语

- 列出技术术语、专有名词、品牌名、缩写
- 与已加载术语表交叉核对
- 对术语表中没有的术语，确定标准译法
- 记录到术语表格中

### 1.3 语气与风格

- 正式还是口语化？是否有幽默、隐喻、文化引用？
- 针对目标受众，译文适合使用什么语体？

### 1.4 翻译难点

识别可能造成翻译困难的内容：

- **理解缺口**：目标读者可能不理解的术语或引用——说明需要什么解释
- **比喻语言**：不能直译的隐喻、习语、表达——说明原意和目标语言处理方式（解释 / 替换 / 保留）
- **结构难点**：长而复杂的句子、文字游戏、双关或需要创造性改写的幽默

**保存 `01-analysis.md`**，格式如下：
```
## Content Summary
[Core argument, author, context, purpose]

## Terminology
[term → translation, ...]

## Tone & Style
[assessment]

## Translation Challenges
- [term/passage] → [challenge type] → [suggested approach]
- ...
```

## 第 2 步：组装翻译提示

主 agent 读取 `01-analysis.md`，并使用 [references/subagent-prompt-template.md](subagent-prompt-template.md) 组装完整翻译提示。内联以下分析内容：

- **目标风格**：解析后的风格预设 + §1.3 中对原文声音的评估
- **内容背景**：§1.1 的摘要
- **术语表**：合并术语表 + §1.2 中从分析提取的术语
- **翻译难点**：§1.4 中的所有难点

保存到 `02-prompt.md`。此提示由 subagent（分块时）或主 agent 自己（非分块时）使用。

## 第 3 步：初稿

保存到输出目录中的 `03-draft.md`。

对于分块内容，subagent 产出此初稿（由分块译文合并而成）。对于非分块内容，主 agent 直接产出。

按照 `02-prompt.md` 翻译全文。应用 SKILL.md 中所有**翻译原则**。

## 第 4 步：批判性审校

主 agent 对照源文批判性审校初稿。将审校发现保存到 `04-critique.md`。此步骤只产出**诊断**——暂不改写。

### 4.1 准确性

- 逐段对照原文
- 核实事实、数字、日期、专有名词
- 标记意外添加、删除或改变的内容
- 检查与术语表的一致性

### 4.2 母语表达

- 标记读起来像“翻译”而不是“写作”的句子——不自然的语序、逐字硬译、生硬措辞
- 对 CJK 目标语言：检查不必要的连接词（因此/然而/此外）、被动语态滥用（被/由/受到）、名词堆叠、过度名词化
- 标记直译后在目标语言中显得不自然的隐喻
- 检查情感色彩是否保留，而不是被抹平
- 说明哪些地方通过重组句子可以提升可读性

### 4.3 注释与改写

- 译者注是否准确、简洁且确实有帮助？
- 标记遗漏的理解难点（需要注释）以及对显而易见术语的过度注释
- 是否遵循了 `02-prompt.md` 中的翻译策略？
- 文化引用在目标语言中是否有效？

**保存 `04-critique.md`**，格式如下：
```
## Accuracy
- [issue]: [location] — [description]

## Native Voice
- [issue]: [example] → [suggested fix]

## Notes & Adaptation
- [add/remove/revise]: [term/passage] — [reason]

## Summary
[Overall assessment: X critical issues, Y improvements]
```

## 第 5 步：修订

应用 `04-critique.md` 中的所有发现，产出修订译文。保存到 `05-revision.md`。

读取 `03-draft.md` 和 `04-critique.md`，修复所有准确性问题，改写不自然表达，调整注释，并改善行文流畅度。

## 第 6 步：润色

将最终版本保存到 `translation.md`。

对 `05-revision.md` 做出版级质量的最终检查：

- 将整篇译文作为独立文章通读——是否像目标语言的母语内容一样流畅？
- 顺平仍然生硬的过渡表达
- 确保全文叙述声音和风格一致
- 最终术语一致性检查
- 核实格式是否正确保留

## Subagent 职责

每个 subagent（每个分块一个）**只**负责产出自己分块的初稿（第 3 步）。主 agent 组装共享提示（第 2 步），并行启动所有 subagent，然后接手批判性审校（第 4 步）、修订（第 5 步）和润色（第 6 步）。

## 分块 Refined 翻译

当内容超过分块阈值并使用 refined 模式时：

1. 主 agent 先对**整篇**文档进行分析（第 1 步）→ `01-analysis.md`
2. 主 agent 组装翻译提示 → `02-prompt.md`
3. 拆分为分块 → `chunks/`
4. 每个分块并行启动一个 subagent（每个都读取 `02-prompt.md` 获取共享上下文）→ 将所有结果合并到 `03-draft.md`
5. 主 agent 批判性审校合并后的初稿 → `04-critique.md`
6. 主 agent 根据审校意见修订 → `05-revision.md`
7. 主 agent 润色 → `translation.md`
8. 最终跨分块一致性检查：术语、叙述流、分块边界处的过渡
