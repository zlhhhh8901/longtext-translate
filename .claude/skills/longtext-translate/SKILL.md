# 文本翻译

本技能提供三条翻译路径，根据文本规模和用户需求自动判断或由用户指定：

1. **普通翻译**：主 agent 在单一上下文中完成翻译，输出目录中只保留最终译文。适合短文本和论证紧密、不宜分片的文章。
2. **长文本翻译**：先分片，再由主 agent 建立共享上下文并委派 subagent 并行翻译各分片，最后合并与自检。适合可稳定拆分的长文。
3. **译稿审校与润色**：对已有译文进行审校和润色。既可承接前两种路径，也可在用户直接提供原文与译稿时独立执行。

## 前置准备

### 第 1 步：规范化源内容

翻译流程只接受 Markdown 输入。若用户提供的是 PDF 或 EPUB 文件，先按对应 ingestion 指南将其转换为本地 Markdown；若用户只要求翻译源材料的一部分，如指定章节、页码或标题范围，则先抽取并保存该范围内容。

**规范化后的 Markdown 文件，是后续所有翻译步骤的唯一输入源。**

| 输入类型 | 动作 |
|------------|--------|
| 文本 / Markdown 文件 | 直接使用 |
| 内联文本 | 保存为 `translate/{slug}.md` |
| PDF 文件 | 按 `references/ingest/pdf.md` 处理并保存为 `translate/{slug}.md` |
| EPUB 文件 | 按 `references/ingest/epub.md` 处理并保存为 `translate/{slug}.md` |
| 只翻译源文本的部分内容 | 抽取指定范围，保存为 `translate/{filename}-part.md` |

`{slug}`：根据内容主题生成的 2–4 个词、采用 `kebab-case` 的短名称。

### 第 2 步：制定并确认翻译方案

**① 整理翻译偏好**

- **目标语言**：默认简体中文，用户可自行指定。
- **目标读者**：默认为希望准确、无障碍理解原文内容的读者，用户可自行指定。
- **用户术语资源**：用户显式提供的术语约束，例如术语表文件、命令中直接写出的术语映射、保留原文或指定译法等要求。非必须项；若有则完整收集并全程应用。

**② 决定翻译策略**

先对源材料做轻量分析，再按下述顺序判断：

1. 用户已明确指定策略，直接按其要求执行。
2. 用户要求中含有“精翻”、“精校”、“审校”、“润色”、“发版级质量”、“出版级”等关键词，在所选翻译路径完成后继续执行审校与润色流程。
3. 依据翻译规模判断：
   - 读取 `references/metadata.json`。若能识别当前模型且匹配到对应条目，使用该条目的 `safeBelow` 与 `chunkAbove` 阈值；否则使用文件顶层的 `fallback`。
   - 估算待译文本词数。低于 `safeBelow` 采用普通翻译。高于 `chunkAbove` 采用长文本翻译。若介于两者之间，继续评估分片风险。
4. 评估分片风险：当原文论证链紧密、概念与指代跨段延续时，采用普通翻译，并在完成摘要中建议审校与润色；否则采用长文本翻译。

**③ 准备输出目录**

明确策略后，在源文件同级目录下创建输出目录，路径格式为 `{source-dir}/{source-basename}-{target-lang}/`。

示例：
- `posts/article.md` → `posts/article-zh/`
- `translate/ai-future.md` → `translate/ai-future-zh/`

若目标目录已存在且是本任务的延续，则直接沿用原有目录及其中间文件。若已存在但并非本任务的延续，则路径改为 `{source-dir}/{source-basename}-{target-lang}-MMDD-HHMM/`，其中 `MMDD-HHMM` 代表当前日期和时间。

**④ 生成分片预览（仅限长文本翻译模式）**

如采用长文本翻译模式，先执行以下命令：

`python3 {baseDir}/scripts/chunk.py preview <file> [--max-words <chunk_max_words>] --output-dir <output-dir>`

其中，`{baseDir}` 为本 `SKILL.md` 所在目录，`<chunk_max_words>` 使用前述阈值中的 `safeBelow`。依赖 `markdown-it-py>=4.0,<5`。

此命令将生成 `chunk-preview.html`，并自动启动本地预览服务，但不会立即创建 `chunks/` 文件夹。用户可通过命令返回的 `preview_url` 查看分片预览页面，按需调整分片边界。若用户调整了边界，并在页面中点击了“确认分片方案”，将方案会自动保存为 `chunk-plan.json`，并在后续被脚本采用；若不调整，直接回到对话确认开始翻译即可，后续脚本会采用默认分片方案。

**⑤ 声明翻译计划并等待确认**

初步确定翻译方式和输出目录后，向用户说明：当前采用的翻译路径、判断依据、目标语言、目标读者、术语约束、输出目录，以及长文本模式下的分片预览入口。用户确认后再开始正式翻译。

## 翻译执行

### 第 1 步：理解内容并确定译法

基于前置准备确定的翻译策略、目标读者和术语约束，深入分析源材料，做出具体译法判断。

**① 内容理解** 核心论点是什么？作者背景、立场和写作语境？原文的目的和预期受众？

**② 术语** 识别需要全局统一的核心术语，与前置准备中收集的用户术语资源交叉核对；对术语表中未覆盖的术语，确定标准译法。

**③ 译法判断**

- **语域锚定**：原文的正式度、口语度处于什么位置？基于目标读者，译文应锚定在何种语域？
- **格式增强许可**：原文有无固有章节或标题结构？论证形式是松散散文还是严密论证？目标语言读者是否需要额外的格式导航，如加粗关键句、插入小标题？
- **注释策略**：基于目标读者，哪些术语或背景概念需要解释？密度如何？
- **句式策略**：原文句长和复杂度特征如何？目标语言需要拆句、重组到什么程度？

**④ 翻译难点** 不能直译的隐喻、习语、表达；长难句、双关、文字游戏等需要创造性处理的结构。

在普通翻译模式下，本步骤仅作为内部推理参考，无需生成分析文件或向用户输出分析内容。

### 第 2 步：翻译

开始翻译前，回顾第 1 步中的四项译法判断，并在翻译过程中贯彻执行。

**必须遵守的原则**：

- **准确第一**：忠实原文，完整保留原文事实、数据、观点、逻辑关系和论证结构。
- **重写，而不只是翻译**：不改变原意的前提下，将内容重写为自然流畅的目标语言，如同母语作者从零创作。句式重组、信息重排和段落节奏调整应以目标语言的自然表达为准。
- **语气与语域匹配**：原文的口语化程度、情感强度、讽刺或幽默，译文必须等价再现；原文是严谨论述，译文同样保持正式语域和精确性。
- **保留与增强 Markdown 格式**：标题层级、链接、图片、代码块等结构性标记须原样保留。增强操作是否启用，由「译法判断」中的格式增强许可决定。斜体、脚注等语义格式应转换为目标语言中自然且等价的表达方式。原文中独立于引用块之外的叙述性插入，应保持原有段落归属。
- **术语标准**：严格遵守用户提供的术语约束。若无术语约束，专业术语使用行业公认的标准译法。首次出现时，如保留源语原文有助于辨识和统一术语，可在译文后用括号标注原文；当源语言为英文、目标语言为中文时，核心术语默认首次标注英文原文。
- **严禁静默纠错**：若原文存在拼写错误、明显 OCR 错字等低争议错误，可在译文中直接修正，但译后必须向用户汇报。

**目标语言为中文时，额外遵守以下执行要求**：

- 将英文长句拆分成中文惯用短句，或将原文松散短句整合为更自然的中文段落节奏。
- 按中文的自然信息排列习惯重组从句和修饰关系，不跟随原文的嵌套顺序。
- 句子是否成立，以中文母语作者的写作直觉为准，而不以逐词对应为准。

**译者注**：是否添加、添加密度如何，由「译法判断」中的注释策略决定。如需添加，格式为粗体括号 `（**解释**）`。

### 第 3 步：译后自检

回源抽查译文，按以下维度快速检查：

- **准确性**：事实、数据、观点、逻辑关系和论证结构无偏移。
- **完整性**：无漏译、无增译、无跳段、无重复。
- **语气**：情感强度和语域匹配原文。
- **术语**：用户指定术语正确应用，核心术语前后一致，首次原文标注策略执行到位。
- **格式**：Markdown 结构性标记完整，叙述性插入段落归属正确。
- **可读性**：无病句、无翻译腔、指代清楚。

局部问题就地修正。若发现跨段落、跨章节的系统性问题，如术语漂移、语气风格不一致或叙述口径摇摆，应在当前译文中尽可能修正明显问题；若仍判断需要全局审校，则继续执行审校与润色流程。

### 第 4 步：完成摘要

向用户汇报时，至少交代以下信息：

- 最终译文保存路径
- 是否存在争议点、不确定之处或建议的下一步
- 本次是否已执行审校与润色

### 长文本翻译模式

同样需先完成第 1 步「理解内容并确定译法」。但若源文件过大导致读取 token 受限，则按下方的「超长文本翻译执行流程」进行。

**一般长文本翻译的执行流程为**：

1. **提取术语**：扫描整篇文档，找出专有名词、技术术语、重复短语。
2. **建立会话术语表**：将提取出的术语与用户术语约束合并，确定一致译法，整理为 `glossary.md`。
3. **组装翻译提示**：按 `references/prompt-template.md` 的第 1 部分组装共享上下文——内联“理解内容”时的判断（目标风格、内容背景和翻译难点），保存为 `prompt.md`。
4. **执行命令将分片落地**：`python3 {baseDir}/scripts/chunk.py materialize <file> [--max-words <chunk_max_words>] --output-dir <output-dir>`
   - 脚本会优先读取 `chunk-plan.json`，否则采用默认分片方案
   - 返回 JSON 中的 `chunk_index` 提供每个 chunk 的编号、词数和起始标题路径
5. **委派 subagent 起草**：为每个分块启动一个 subagent，按可承受的并发能力分批执行（模板第 2 部分）。每个 subagent 会读取 `prompt.md` 获取共享上下文，接收分块位置信息，翻译自己的分块并保存为 `chunks/chunk-NN-draft.md`。
6. **合并**：所有 subagent 完成后，按顺序合并已翻译分块。若存在 `chunks/frontmatter.md` 则置于开头。保存为 `translation.md`。所有源分块与已翻译分块均保留在 `chunks/` 中。

译后自检由主 agent 对合并后的初稿进行。除前述质量门禁外，还需额外检查：论证接续、指代清晰度、语气一致性、术语一致性，以及是否存在重复或漏译。处理方式同上：局部问题就地修正，系统性问题在修正基础上通过完成摘要建议审校润色。

最后，输出完成摘要。

#### 超长文本翻译执行流程

若源文件过大导致无法稳定扫描整篇全文，则先建立整体认识，包括书名与作者、目录结构、章节主题、核心领域和术语密集区，再进入分阶段交付。

若整项任务由多个批次组成，则先全局分片一次，后续按连续 chunk 范围推进。每完成一批都更新 `glossary.md` 与 `prompt.md`，并按顺序重新组装所有已完成分块，覆盖写入 `translation.md` 作为截至当前批次的累计译文快照，再进入下一批。

1. **建立整体认识**：通过标题、目录、前言、章节摘要和抽样段落建立全局认识，比如书名与作者、大致章节数、目录结构、核心主题与学科领域。
2. **确定首批交付范围**：基于 `chunk_index` 选择连续 chunk 范围，优先让批次落在完整章节、完整 section 或完整论证单元上。
3. **滚动维护共享上下文**：`glossary.md` 和 `prompt.md` 作为可继承、可补充的共享资产，服务后续批次，减少术语漂移和语气偏移。

## 译稿审校与润色

审校与润色用于降低误译风险，并使译文作为自然的目标语言文章成立。本流程在以下情形触发：

- 用户明确要求精翻、审校、润色或出版级质量
- 主 agent 在译后自检中发现无法通过局部修正解决的系统性问题

执行总则：先诊断，再修订，后润色。具体流程覆盖两种情况：

1. **已有完整翻译过程**：译文由本技能前述流程逐步生成，上下文与中间文件完整。
2. **直接提供原文与初稿**：用户直接提交源材料与译文初稿，未经过翻译流程。

详细执行细节阅读：`references/polish.md`。
