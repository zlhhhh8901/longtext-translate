# 译文审校

审校分两个阶段执行：先逐段对照原文，修正可核实的问题；再脱离原文，将译文作为独立文章通读顺平。两个阶段方法不同，目的互补——对照审校保证准确，脱稿顺平保证译文读起来像一篇自然的目标语言文章。

## 流程

### 情况一：承接翻译流程

翻译执行完成且用户确认进入审校后：

1. 主 agent 将 `translation.md` 复制为 `draft.md`，作为审校前的译稿快照。
2. 主 agent 按下方「subagent 审校提示」组装 prompt，委派 subagent 执行对照审校，输出 `critique.md`。
3. 主 agent 读取 `critique.md`，逐条回源原文核实，对成立的发现进行修订。
4. 对照修正完成后，主 agent 将修订后的译文作为独立文章通读顺平，最终保存为 `translation.md`。

### 情况二：用户直接提供原文与译稿

用户直接提供原文与已有译稿时，主 agent 全程执行审校：

1. 将原材料按前置流程规范化为 Markdown，并按主流程确定输出目录。
2. 将用户提供的译稿保存为 `draft.md`。
3. 主 agent 严格对照原文与 `draft.md`，按审校要点逐段检查，生成 `critique.md`。
4. 主 agent 基于 `critique.md` 修订。
5. 对照修正完成后，主 agent 将修订后的译文作为独立文章通读顺平，最终保存为 `translation.md`。

## 审校原则与要点

逐段对照原文与 `draft.md`。审校只记录语义忠实与可回源证伪的问题，不要求译文与原文在结构和版式上逐项同构。为提升可读性而添加的小标题、加粗、分段或分隔线、`（注：）` 式补充说明，以及中文排版和标点规范化，不视为增译；仅当这些处理引入事实错误、改变原意、增添原文不存在的观点或论证，或明显误导读者时，才记为问题。

**准确与完整**
- 准确性：事实、数据、观点、逻辑关系和论证结构无偏移。
- 完整性：无漏译、无内容性增译、无跳段、无重复。

**可读性**
- 句法归化：检查是否存在僵硬套用原文词序、句式的直译结构。
- 长句分解：根据目标语言特性拆分长句，理顺逻辑连接。

**语域与语气**
- 情感匹配：准确传达原文情感浓度和体裁风格。
- 特殊修辞：保留反讽、幽默或特定人格化语气。

**术语一致性**
- 如有 `glossary.md`，需严格遵守。
- 核心术语全文一致。
- 未覆盖的专业术语使用行业公认的标准译法。
- 专业术语/人名/书名首次出现时，在译文后用括号标注原文。全文只标注一次。

**Markdown 格式**
标题、列表、链接、图片、代码块、脚注等结构性标记完整保留。

## 诊断报告格式（`critique.md`）

仅记录可证伪的问题。某类无问题可省略该节，禁止为填满模板而编造问题。参考格式：

```markdown
## ...
- [问题]：[位置] — [描述]

## ...
- [问题]：[示例] → [建议修改]
```

## subagent 审校提示

仅用于情况一。主 agent 按以下模板组装 prompt 并委派 subagent：

```text
你是译文审校者，请读取以下材料并输出 critique.md，严禁修改其他任何文件。

- 原文：{原文路径}
- 待审译稿：{draft.md 路径}
- 术语表（如有）：{glossary.md 路径}
- 输出：{critique.md 路径}

## 审校目标

{主 agent 在此内联审校目标：目标语言、目标读者、语域要求、本轮侧重点等。3-5 句。}

## 审校原则与要点

{{...}}

## 诊断报告格式

{{...}}
```

组装时，将上文「审校原则与要点」和「诊断报告格式」两节的完整内容分别替换 prompt 中对应的 `{{...}}` 占位符，再发送给 subagent。

## 通读顺平

对照修正完成后，脱离原文，将译文作为独立的目标语言文章通读，以保守原则顺平明显生硬之处：

- 消除翻译腔：按目标语言习惯重组仍带原文句式痕迹的表达，使译文读起来像母语写作。
- 顺平衔接：修复读起来明显卡顿的句间过渡和断裂的段落衔接。
- 文化转化：隐喻、俚语和文化参照转化为符合目标语言习惯的表达，确保读者能自然理解。
- 叙述声音：保持全文语气、判断力度和风格协调——出现与全文基调明显偏离的段落时拉回，不强行统一所有段落的松紧度。
- 保守原则：只处理明显生硬之处，不为“更好”而重写已经通顺的句子。
